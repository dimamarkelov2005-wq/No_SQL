4. Запросы Aggregation Pipeline (не менее 10)Запрос 1 ($match по строковому полю)Фильтрация товаров из категории Notebook.JavaScriptdb.products.aggregate([
  { $match: { category: "Notebook" } }
])
Запрос 2 ($match по диапазону значений)Поиск товаров с ценой от 50 000 до 200 000 KZT.JavaScriptdb.products.aggregate([
  { $match: { price: { $gte: 50000, $lte: 200000 } } }
])
Запрос 3 ($match с условием $or)Выбор товаров из категорий Audio или Wearables.JavaScriptdb.products.aggregate([
  { $match: { $or: [{ category: "Audio" }, { category: "Wearables" }] } }
])
Запрос 4 ($project — проекция полей)Вывод только названия, категории и цены товара без поля _id.JavaScriptdb.products.aggregate([
  { $project: { _id: 0, name: 1, category: 1, price: 1 } }
])
Запрос 5 ($project с вычисляемым полем)Расчет общей стоимости складского остатка для каждого товара (inventoryValue = price * stock).JavaScriptdb.products.aggregate([
  { 
    $project: { 
      _id: 0, 
      name: 1, 
      price: 1, 
      stock: 1, 
      inventoryValue: { $multiply: ["$price", "$stock"] } 
    } 
  }
])
Запрос 6 ($group — агрегация по категориям)Расчет количества товаров, средней цены, суммарного остатка, минимальной и максимальной цены по каждой категории.JavaScriptdb.products.aggregate([
  {
    $group: {
      _id: "$category",
      totalProducts: { $sum: 1 },
      avgPrice: { $avg: "$price" },
      totalStock: { $sum: "$stock" },
      minPrice: { $min: "$price" },
      maxPrice: { $max: "$price" }
    }
  }
])
Запрос 7 ($sort и $limit — ТОП-5 товаров)Получение ТОП-5 самых дорогих товаров в наличии (stock > 0).JavaScriptdb.products.aggregate([
  { $match: { stock: { $gt: 0 } } },
  { $sort: { price: -1 } },
  { $limit: 5 },
  { $project: { _id: 0, name: 1, price: 1, stock: 1 } }
])
Запрос 8 ($unwind — работа с массивами)Разворачивание массива тегов tags и подсчет популярности каждого тега.JavaScriptdb.products.aggregate([
  { $unwind: "$tags" },
  { $group: { _id: "$tags", count: { $sum: 1 } } },
  { $sort: { count: -1 } }
])
Запрос 9 ($lookup — объединение коллекций)Соединение заказов (orders) с покупателями (customers) по полю customerId.JavaScriptdb.orders.aggregate([
  {
    $lookup: {
      from: "customers",
      localField: "customerId",
      foreignField: "customerId",
      as: "customer"
    }
  },
  { $unwind: "$customer" },
  {
    $project: {
      _id: 0,
      orderId: 1,
      total: 1,
      status: 1,
      "customer.name": 1,
      "customer.city": 1
    }
  }
])
Пояснение полей $lookup:from: целевая коллекция для объединения (customers).localField: связующее поле в исходной коллекции orders (customerId).foreignField: связующее поле в целевой коллекции customers (customerId).as: имя нового массива, куда помещаются найденные совпадающие документы (customer).Запрос 10 (Многоэтапный Pipeline из 5 этапов)Выборка популярных товаров (рейтинг ≥ 4.5), группировка по категориям, расчет средней цены, фильтрация категорий со средней ценой выше 100 000 KZT и сортировка по убыванию.JavaScriptdb.products.aggregate([
  { $match: { rating: { $gte: 4.5 } } },
  { $group: { _id: "$category", avgPrice: { $avg: "$price" }, count: { $sum: 1 } } },
  { $match: { avgPrice: { $gt: 100000 } } },
  { $sort: { avgPrice: -1 } },
  { $limit: 3 }
])
5. Индексы и анализ производительности (explain)Эксперимент 1. Запрос без индексов (COLLSCAN)Запрос:JavaScriptdb.products.find({ category: "Notebook" }).explain("executionStats")
План выполнения: COLLSCAN (сканирование всей коллекции).Результаты: Просмотрены все 30 документов (totalDocsExamined: 30), чтобы вернуть 3 документа (nReturned: 3). Ключи индекса не использовались (totalKeysExamined: 0).Эксперимент 2. Создание и проверка простого индекса (IXSCAN)Создание индекса:JavaScriptdb.products.createIndex({ category: 1 })
Проверка:JavaScriptdb.products.find({ category: "Notebook" }).explain("executionStats")
План выполнения: IXSCAN (сканирование индекса по категории).Результаты: Просмотрено ровно 3 ключа (totalKeysExamined: 3) и 3 документа (totalDocsExamined: 3). Число сканируемых документов снизилось с 30 до 3.Эксперимент 3. Создание и проверка составного индексаЗапрос с фильтрацией и сортировкой:JavaScriptdb.products.find({ category: "Notebook" }).sort({ price: 1 })
Создание составного индекса:JavaScriptdb.products.createIndex({ category: 1, price: 1 })
Проверка:JavaScriptdb.products.find({ category: "Notebook" }).sort({ price: 1 }).explain("executionStats")
План выполнения: IXSCAN. Данные в индексе отсортированы по price внутри каждой категории, поэтому в плане выполнения отсутствует отдельная ресурсоемкая стадия SORT (память на сортировку в оперативной памяти не тратится).Эксперимент 4. Анализ принципа ESR (Equality, Sort, Range)Целевой запрос:JavaScriptdb.products.find({ category: "Notebook", rating: { $gte: 4.5 } }).sort({ price: 1 })
Тестирование двух вариантов индексов:Индекс { category: 1, price: 1, rating: 1 } (ESR compliant):E (Equality): category: "Notebook"S (Sort): price: 1R (Range): rating: { $gte: 4.5 }Результат: Запрос эффективно считывает данные из индекса прямо по цепочке без вызова отдельной стадии в памяти in-memory SORT.Индекс { category: 1, rating: 1, price: 1 }:При таком порядке диапазонный фильтр (rating) ставится перед сортировкой (price). Индекс не может одновременно выполнять упорядоченный выбор и сортировку по следующему полю, из-за чего MongoDB вынуждена выполнять стадию SORT в оперативной памяти.6. Ответы на контрольные вопросыЧто такое Aggregation Pipeline?Это конвейер обработки данных в MongoDB, состоящий из последовательных этапов (stages), где результат работы одного этапа передается на вход следующему.Для чего используется $match?Для фильтрации массива документов по заданным условиям (аналог блока WHERE в SQL).Чем $project отличается от обычной фильтрации?$project изменяет форму документов (выбирает определенные поля, исключает _id, создает новые вычисляемые поля), тогда как фильтрация лишь отбирает сами документы.Для чего применяется $group?Для объединения нескольких документов в один по общему ключу с возможностью расчета агрегированных метрик (сумма, среднее и т.д.).Что означает поле _id внутри $group?Задает ключ (поле или выражение), по которому производится группировка документов.Для чего используются $sum, $avg, $min и $max?Это математические аккумуляторы внутри $group для подсчета количества/суммы, среднего значения, минимального и максимального значений соответственно.Что делает $unwind?Разворачивает массив внутри документа, создавая отдельный дубликат документа для каждого элемента массива.Для чего применяется $lookup?Для выполнения левого внешнего соединения (LEFT OUTER JOIN) с другой коллекцией в той же базе данных.Что такое индекс MongoDB?Специальная структура данных (B-дерево), хранящая небольшую часть данных коллекции в легкодоступном виде для ускорения поиска документов.Чем простой индекс отличается от составного?Простой индекс построена по одному полю, а составной (Compound Index) — по двум или более полям одновременно.Что означает COLLSCAN?Collection Scan — полное сканирование всех документов коллекции из-за отсутствия подходящего индекса.Что означает IXSCAN?Index Scan — поиск документов с использованием индекса, при котором сканируется только часть ключей.Для чего используется explain("executionStats")?Для получения подробного отчета о плане и статистике реального выполнения запроса (время, просмотренные ключи/документы).Что показывают totalDocsExamined и totalKeysExamined?totalDocsExamined: количество просмотренных документов в коллекции.totalKeysExamined: количество просмотренных записей/ключей в индексе.Почему индекс может ускорять чтение, но увеличивать стоимость записи?Потому что при каждой операции вставки (insert), обновления (update) или удаления (delete) MongoDB должна обновлять не только коллекцию, но и все созданные на ней индексы.Почему порядок полей составного индекса важен?Потому что индекс сортирует данные сначала по первому полю, затем по второму и т.д. Если порядок полей в индексе не совпадает с логикой запроса, индекс может оказаться неэффективным.Что означает принцип ESR?Правило порядка полей в составном индексе: Equality (поля точного равенства) -> Sort (поля сортировки) -> Range (поля диапазонной фильтрации).Почему нельзя оценивать эффективность индекса только по executionTimeMillis на маленьком наборе данных?На маленьком объеме данных (например, 30 документов) время выполнения запроса с индексом и без него близко к 0 миллисекунд. Истинную эффективность показывает снижение totalDocsExamined.Как Access Patterns связаны с проектированием индексов?Индексы должны проектироваться строго под реальные паттерны доступа и частые запросы приложения, а не добавляться случайно на каждое поле.В каких случаях индекс может оказаться бесполезным?Когда запрос выбирает большую часть документов коллекции, когда используются отрицания ($ne), селективность поля крайне низкая (например, пол или boolean), либо когда порядок полей в составном индексе нарушает принцип ESR.8. Итоговый выводВ ходе выполнения лабораторной работы были освоены основные этапы Aggregation Pipeline в MongoDB ($match, $project, $group, $sort, $limit, $unwind, $lookup). На практике подтверждено, что использование индексов превращает поиск типа COLLSCAN в IXSCAN, существенно снижая число сканируемых документов (totalDocsExamined). Также была доказана важность соблюдения правила ESR (Equality, Sort, Range) при построении составных индексов для предотвращения операций сортировки в оперативной памяти (in-memory SORT).
